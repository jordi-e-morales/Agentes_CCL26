# Dependencias de Python del proyecto.
#
# Se instalan en el venv de la raiz del repo, que crea lab/bootstrap.sh.
# Nunca en el Python del sistema.
#
# Por ahora solo esta lo minimo para el segmento 1: hablarle al endpoint de
# vLLM, que expone la API de OpenAI. Las dependencias de SLIM y de OpenTelemetry
# entran cuando esten validadas, no antes.
#
# Las versiones se congelan despues de la primera corrida buena:
#   .venv/bin/pip freeze > requirements.lock.txt
# y el dia del evento se instala desde el .lock, no desde este archivo.

openai

# Cliente de PostgreSQL para el servidor de herramientas (herramientas/).
# psycopg 3, con [binary] para no compilar nada en el host.
psycopg[binary]

# El puente de herramientas (spike-mcp/). SDK oficial de MCP: trae servidor y
# cliente. Version 2.x, que NO es compatible con los ejemplos de la 1.x.
mcp

# El spike de SLIM (spike-slim/). Descartado como transporte (CLAUDE.md §3),
# se conserva por lo aprendido. Es el transporte de la malla: paquete oficial
# de AGNTCY, trae el nodo embebido en Rust ademas de las bindings de Python.
# Se instala aqui porque el spike decide si SLIM entra al proyecto o no.
slim-bindings

# Validacion del esquema (esquema/valida.py). Es dependencia de desarrollo,
# no la necesita nada que corra el dia del evento.
jsonschema
